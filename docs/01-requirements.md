# 需求与验收

## 用户、输入和目标

运营人员输入活动主题、预算和截止时间，需要得到一个在模拟预算、预计时间内可执行的内容活动方案。数据集和业务工具均为合成示例，目标是证明规划和错误处理流程，不代表素材授权或真实制作能力。

输入为 JSON 对象：`topic`（非空文本）、`budget`（非负数或数字字符串，最多两位小数）、`deadline`（日期或带时区的 ISO 日期时间）。缺少字段时返回 `needs_input`，不请求模型；非法输入返回 `invalid_input`。

## 交付和状态

输出任务计划、各步骤状态与尝试、工具结果、已发生费用、方案预计总费、计划或未完成原因，以及可审阅的 Trace。方案保存只表示规划完成；实际编辑仍为 `pending`。

成功标准：

1. 正常输入能得到预算和预计完成时间均合规的已保存方案。
2. 缺预算或截止时间时提示缺失字段，不调用模型和工具。
3. 模型观察到工具失败、部分成功或超预算后，能选择下一动作或结束；失败不能被记为成功。
4. 预算 10 时，估算 12 的方案不可保存；可再估算 8 的候选方案。无可行方案时说明已知缺口和估算范围。
5. 相同任务重复执行不重复计费或保存；失败后续跑保留已完成结果。
6. 过程有调用上限；每组记录包含动作、参数、结果和简短依据。

实际真实模型验收状态和本地测试结果见 [评估](03-evaluation.md)。

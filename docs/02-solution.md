# 方案设计

## 调用流程

输入校验 → 加载或建立 SQLite 任务 → 模型选择一个动作 → 参数和业务约束校验 → 运行本地工具 → 将实际结果作为工具消息交回模型 → 继续、保存或结束。每次运行模型、工具各最多 20 次，达到上限返回 `incomplete`。

真实模式向配置的 Chat Completions 接口发送工具定义，由模型产生工具调用；程序不为真实模型硬编码下一个业务动作。为保证先观察再决策，一次返回多个工具调用时全部拒绝，并将错误返回模型。普通文本结束、非法参数、超时或接口错误均不能冒充成功。

模型动作里的 `reason` 是面向评审的简短业务依据，不是内部思维过程。对支持思考字段的兼容服务，当前会话在内存中原样回传其 `reasoning_content`，不写入 Trace 或 SQLite；续跑时只发送保存的业务结果与步骤摘要。

离线 `MockModel` 使用明确的确定性策略：先高质量估算，超限时尝试另一素材；脚本工具失败时选择备用模板。它只证明状态机和业务守卫，不证明真实大模型决策。[OpenAI 工具调用流程](https://developers.openai.com/api/docs/guides/function-calling)、[DeepSeek 工具调用](https://api-docs.deepseek.com/guides/tool_calls/)和 [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)是协议参考；未使用 Agent 框架。

## 费用、时间和业务守卫

费用均为模拟单位：检索 0、生成脚本 2、估算 0、保存 0；素材授权高质量 6、基础 2，后续编辑 4。故成功生成脚本后：高质量总额为 `已发生 2 + 授权 6 + 编辑 4 = 12`；基础方案为 `2 + 2 + 4 = 8`。失败模拟为 0 费用、1 分钟；费用表在 [catalog.json](../data/catalog.json)。

模拟检索、脚本、估算、保存分别耗时 5、15、1、1 分钟，编辑预计 60 分钟。工具按表推进模拟时钟；继续执行时取现实时间和模拟时钟的较晚值，不能因暂停绕过截止时间。

工具调用前检查费用和当前截止时间；保存前重新校验素材、脚本、与素材匹配的最新估算、已发生费用、预算以及完成剩余编辑的时间。搜索部分成功时保留可用素材及 `partial` 尝试，不能将该次尝试伪装为成功。

## 状态与约束

SQLite 中以规范化输入及模式的摘要作为任务标识，存储状态快照、每次工具尝试和 Trace。失败步骤不会覆盖此前成功素材；通用脚本不依赖某个素材，变更候选素材可复用。重复完成的任务不再次调用模型，未完成任务通过 `--resume` 显式续跑。

本实现以单进程本地演示为目标：没有并发锁、外部真实工具的分布式幂等、任务取消或生产级安全审计。数据库中的模拟费用不能推断真实模型 API 账单或实际制作支出。
